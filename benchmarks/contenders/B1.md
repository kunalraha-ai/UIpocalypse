# QA Test Report — CreditCraft (http://localhost:3124)

**Method:** Black-box testing with Playwright 1.65.1 + headless Chromium (no application source files read; only HTTP traffic and DOM observation). Tests covered: all 7 routes + 404 handling, auth flows, search, promo, recommendations, newsletter, theme/footer button, API edge cases (punctuation matrix, long/empty/malformed payloads, HTTP methods), keyboard navigation, a11y checks, JS-disabled SSR, and responsive viewports (320/375/768/1024px, 200% zoom).

## Bugs found

**1. [Critical] Quick sign-in buttons fail — authentication is completely broken, locking every authenticated page.**
- Repro: Go to `/login`, click **"Sign in as Alice"** (or "Sign in as Bob").
- Result: `POST /api/auth/login` with `{"email":"alice@example.com","password":"secret123"}` returns **401**; UI shows "Invalid email or password". 150 email/password combinations (including the exact credentials the buttons send) were all rejected — no login is possible at all.
- Consequence: `/credits`, `/checkout`, `/orders`, `/profile`, `/settings` are unreachable — they redirect to `/login`. Roughly 5/7 of the app is dead.

**2. [High] Search API crashes (HTTP 500 "Search failed") on almost all punctuation.**
- Repro: On the homepage type `lamp!` (or `lamp?`, `chair(s)`, `desk+chair`, `50%`, `under$50`, `a@b`, `x_y`, `a/b`, or anything containing tab) and press Enter; or `GET /api/search?q=lamp%21`.
- Result: `500 {"error":"Search failed"}`; UI shows "Search failed".
- Exact matrix: fails on `` ! " # $ % & ( ) * + / : ; < = > ? @ [ \ ] ^ _ ` { | } ~ `` and tab/newline; works only for letters, digits, space, and `' , - .`

**3. [High] Newsletter "Subscribe" performs a native full-page GET navigation — no subscription happens, no feedback, email exposed in URL.**
- Repro: On the homepage, enter `test@example.com` in the Newsletter box and click **Subscribe**.
- Result: the page navigates to `/?email=test%40example.com`. No POST/API request is made, nothing is stored, no confirmation appears.

**4. [High] "See today's promo" button calls a nonexistent endpoint and silently does nothing.**
- Repro: On the homepage click **"See today's promo"**.
- Result: `GET /api/promo` → **404**. No promo is displayed and no error is shown in the UI.

**5. [Medium] Footer "✦" button is completely dead and has no accessible name.**
- Repro: On any page, click the "✦" button in the footer.
- Result: zero DOM changes, no click event listeners attached. Icon-only button with no aria-label/title.

**6. [Medium] "Load recommendations" takes ~4 seconds with no loading indication whatsoever.**
- Repro: Click **Load recommendations** once and observe; then click it 4× rapidly.
- Result: the response takes **~4,060ms**; no spinner, no aria-busy, no skeleton. Rapid clicking produces no additional feedback.

**7. [Medium] After a failed search, stale results from the previous query remain on screen together with the error.**
- Repro: Search `desk` (shows results), then search `desk!!` (500).
- Result: the UI simultaneously shows the old results, the "Search failed" error, and the input holding `desk!!`.

**8. [Medium] No empty state when search matches nothing.**
- Repro: Search `xyzzy`.
- Result: API returns 200 with `count: 0`, the results list is rendered empty, and no "no results" message appears.

**9. [Medium] Horizontal overflow on narrow viewports (≤337px): product cards don't collapse.**
- Repro: Open the homepage at 320×640.
- Result: `scrollWidth=338 > clientWidth=320` — the page scrolls horizontally.

**10. [Medium] Login form has no client-side validation and misleading errors; no rate limiting; malformed requests treated identically.**
- Repro: On `/login`, click **Sign in** with both fields empty. Also `POST /api/auth/login` with body `not json`.
- Result: empty fields submit straight to the server → 401 → UI shows "Invalid email or password" even though nothing was entered. Malformed JSON also returns 401 instead of 400. No name/autocomplete attributes. No throttling.

**11. [Low] Accessibility gaps: no `<h1>` anywhere except the 404 page, no skip link, no `prefers-reduced-motion` support.**

**12. [Low] Favicon is missing.**

**13. [Observation] The dev server died mid-testing and never came back.**
- At ~11:13 IST the server on port 3124 stopped accepting connections entirely and was still down 6+ minutes later.

**Verified working (no bug):** protected routes redirect to /login quickly; React escaping prevents XSS; API returns proper 405s; SSR renders with JS disabled; keyboard tab order logical; search trims whitespace; no console errors on clean load.
